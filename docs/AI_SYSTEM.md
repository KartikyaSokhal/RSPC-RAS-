# Topic-aware tutor implementation

`DatabaseRetrievalProvider.retrieve` resolves current published notes/PDF pages, then at most two explicitly reviewed related/prerequisite topics when requested. Ancestor visibility and snapshot versions are required. Selected text must match a current source ID, text substring and revision. History helps interpret intent; it is not factual evidence. Ranking is bounded lexical retrieval, not embeddings or a claim of semantic-search quality.

Limits: question 2,000 characters, six history messages/4,000 total history characters, selection 1,000 characters, at most 12 chunks/18,000 candidate characters with 2,400-character windows. The final UTF-8 byte upper bound plus framing is capped at 16,000 input tokens; oldest history and lower-priority chunks are trimmed before reservation. Output cap 1,000 tokens. Current evidence is prioritized, with slots reserved for requested related evidence. Empty evidence abstains without calling the provider.

The Gemini adapter uses the pinned official SDK, a 30-second timeout, one attempt, JSON response mode, no tools and thinking budget zero. System instructions treat all evidence/history as untrusted data. Returned JSON structure is validated; factual responses require manifest IDs, no model-created URLs/HTML, and a fresh publication/resource check. Citation URLs are constructed server-side. These checks validate provenance/scope, not factual entailment; human/live evaluation is still required.

`AI_ENABLED=false` and `AI_GUEST_ENABLED=false` are defaults. Live mode additionally requires an approved model, server-only key, positive daily cap and positive input/output rates. Demo settings clear credentials and select only DemoProvider, which quotes retrieved evidence and explicitly labels itself mocked.

Costs use integer microcurrency units: `AI_DAILY_BUDGET_MICRO` is daily maximum; `AI_INPUT_RATE_MICRO` / `AI_OUTPUT_RATE_MICRO` are the chosen currency's micro-units per million tokens. Example arithmetic must be derived from the approved model's current price, including all billed usage; no rate/cap is approved yet. A conservative reservation covers maximum input/output before the one provider call. A conditional database transaction reserves global/day, visitor/day, IP/day and visitor/minute buckets and checks one live request per visitor. Limits default to 20/day per visitor, 100/day per IP, five/minute. Unknown/timeout billing retains the full reservation; only bounded known actual usage releases unused cost. Lock contention fails closed. PostgreSQL settlement locks the request row before checking completion; eight-thread reservation and two-thread settlement regressions verify the cap and prevent duplicate release. SQLite remains covered by the isolated race check. Expired in-flight claims release availability, not money.

CSRF plus a signed 24-hour HTTP-only visitor cookie protect guest POST initialization. Raw IPs/prompts/answers are not stored in budget tables. The IP is REMOTE_ADDR unless an explicitly trusted proxy overwrites X-Real-IP. Cookie reset does not bypass IP/global ceilings. All workers must share the same PostgreSQL quota database; no unrestricted retry or client-controlled model/rates.
